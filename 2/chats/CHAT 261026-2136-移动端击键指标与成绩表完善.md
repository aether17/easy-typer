> 发文时，有“击键”、“速度”、“键准”、“达标次数”这几个指标，击键现在显示的是移动端无效。不过我现在使用的输入法，可以在每次按键时，先将字母输入到文本框里，上屏时再替换成文本。这样的话，能否让移动端的击键可用？另外，这样的话，键准是不是会更准？比如还没有上屏时回改，是不是也会记录上？

⏺ 我先看一下“击键”和“键准”目前怎么统计，以及输入法组字、回改时的事件处理，再判断你这种输入法能记录到哪些操作。

⏺ 目前确实是按“移动设备”直接禁用了击键门槛；底层统计主要依赖键盘事件，没有利用编码文本的变化来补记。你描述的输入法提供了可利用的信息，但要区分“删除编码”和“编码正常替换成汉字”，否则键准反而会算错。

⏺ **可以支持，而且有机会把未上屏时的删改也计入键准。**前提是你描述的每一步编码变化，网页都能收到。
我看了当前代码：
- “移动端无效”是程序按设备类型直接禁用的，并没有检测输入法是否支持。[代码位置](/home/aether/repos/github/easy-typer/src/views/Kata.vue:206)
- 击键主要靠 `keydown` 统计；未上屏的退格依赖能否收到明确的 `Backspace`。目前没有通过编码文本的变化来补记，所以**现在不能保证记全**。[代码位置](/home/aether/repos/github/easy-typer/src/components/Racing.vue:156)
你这种输入方式可以利用组字事件和输入事件来补充统计；浏览器规范提供了这些事件，但实际效果仍需用你的输入法验证。[W3C 输入事件说明](https://www.w3.org/TR/input-events-2/#input-event-order-during-composition)
例如输入过程是：
`空 → n → ni → n → ni → 你`
适配后可以识别出 **3 次字母输入、1 次退格**。其中：
- `ni → n`：未上屏时删掉编码，可以影响键准。
- `ni → 你`：正常上屏，不能算成删除或回改。
- 最后选字的操作是否能准确计为一次击键，需要看实际事件。
**键准会更能反映操作失误，但数值可能下降**，因为原先漏掉的退格也计入了。按当前统计口径，未上屏删编码应归入“退格”；“回改”主要统计上屏后删掉的文字。键准本身仍是根据退格、清空编码和回改推算的指标。[计算公式](/home/aether/repos/github/easy-typer/src/store/racing.ts:118)
你现在用的输入法和浏览器分别是什么？这能帮助确定如何适配，尤其是选字、自动上屏和删除编码的识别。
