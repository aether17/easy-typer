我查了源码，找到与这个现象直接相关的可疑逻辑：输入框聚焦后，页面一滚动，就把整个 `body` 改为固定定位，再按“滚动距离减 62 像素”移动；手指滑动时还会强制让输入框失焦、收起键盘。这可能和浏览器为软键盘自动调整可视区域的行为冲突。**这是明确的排查入口，但尚未经你的设备复现验证，不能说已经确认唯一根因。** [相关源码](https://github.com/owenyang0/easy-typer/blob/main/src/store/util/common.ts#L82)
自建时需要实际改代码，单纯换个域名部署，问题仍会存在。我建议修复范围包括：
- **重做手机练习区布局**：根据键盘弹出后实际剩余的可视高度布局，让原文和输入框同时可见；长文章只在原文区域内滚动。移除上述整体移位和滑动收键盘逻辑。浏览器提供的 `VisualViewport` 可以用来跟踪这部分可见区域。[接口说明](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)
- **保留指标过关机制**：常用前几百字分组、速度与准确率门槛、失败重打或乱序、达标进入下一组。
- **核查手机准确率算法**：木易当前“键准”依赖按键数、退格和回改统计。手机上应重点验证这些数据；如果不可靠，就改成明确的“上屏错误累计统计”，打错后改正仍保留错误记录，避免最后改对就变成满分。[现有统计实现](https://github.com/owenyang0/easy-typer/blob/main/src/store/racing.ts#L118)
另外，自建还需要处理一个容易漏掉的地方：**练习文本列表及部分文章通过作者网站的 API 加载**，因此不能只部署前端就假定完整可用。常用字表、固定练习文和自定义文本应改成本地加载。[文本加载源码](https://github.com/owenyang0/easy-typer/blob/main/src/api/easyTyper.ts)
